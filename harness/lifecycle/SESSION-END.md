# 会话结束检查清单（SESSION-END）

结束会话前，必须按序完成以下检查并留下持久记录。
**未完成本清单，本会话不算结束。**

## 1. 验证所有声明（verification-before-completion 联动）

- [ ] 本会话中每一句"完成 / 修好 / 通过"的声明，是否都有现场运行验证命令的输出作为证据？
- [ ] 如声称测试通过：本会话最后是否运行过测试并看到 0 failures？

没有新鲜证据的声明必须回退为"未验证"。

## 2. 更新会话日志

按 `harness/reports/session-log-template.md` 创建或追加本次会话日志，重点填写：

- [ ] 本次完成的事项（附验证输出摘要）
- [ ] 未完成事项及原因
- [ ] 下一步建议（下一个会话的起点）

## 3. 记录反馈（finding-bound fixes）

- [ ] 本会话发现的问题是否已写入 `harness/feedback/FEEDBACK-LOG.md`？
- [ ] 每个问题是否标注了状态：待修复 / 已修复（附修复标识）/ 不修复（附理由）？

## 4. 工作区状态

- [ ] 记录当前分支、未提交改动概况（写入会话日志）。
- [ ] 如处于收尾节点，按 `superpowers/skills/finishing-a-branch.md` 向用户呈现
      Merge / Push & PR / Keep / Discard 四选一菜单，并按选择执行。
- [ ] 未归档的 openspec 变更、未执行的计划，在会话日志中明确标注。

---

全部完成后，在会话日志末尾写："会话结束检查已完成"。
