# 会话开始检查清单（SESSION-START）

每次新会话开始、动任何代码之前，必须按序完成以下检查。
**未完成本清单，不得执行任何任务。**

## 1. 恢复上下文（读持久报告）

- [ ] 列出 `harness/reports/` 下所有会话日志，按日期排序，完整阅读最近 1 次会话日志。
- [ ] 阅读 `harness/feedback/FEEDBACK-LOG.md` 中所有 **未解决** 状态的问题。

## 2. 重复工作检测（repeated work）

逐项确认，避免重做：

- [ ] 最近会话日志中的"未完成事项"——本次会话是否要继续？
- [ ] `superpowers/plans/` 中是否存在尚未执行完的计划？
- [ ] `openspec/changes/` 中是否存在未归档的活动变更？
- [ ] 本次用户请求是否与已归档变更（`openspec/changes/archive/`）重复或冲突？

若检测到疑似重复，**先向用户说明已存在的相关工作**，经确认后再决定复用还是重做。

## 3. 项目状态确认

- [ ] 运行 `git status`，确认当前分支与工作区状态。
- [ ] 确认当前是否已在隔离 workspace（worktree）；正式开发不得在 main/master 上直接进行。
- [ ] 运行项目 baseline 验证命令（测试套件），确认基线全绿。

## 4. 待处理反馈检查

- [ ] FEEDBACK-LOG 中是否有与本次任务相关的历史反馈？如有，必须将其纳入本次任务约束。

---

完成以上检查后，在本会话日志中记录："会话开始检查已完成"，再开始执行用户任务。
