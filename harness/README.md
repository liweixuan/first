# Harness 层 —— 外层代理协调

本目录是 **外层编码代理 Harness** 在项目侧的治理层。它不直接产出产品代码，
而是让代理的每一次会话都变成可追溯、可恢复、可反馈的过程。

## 目录职责

| 目录/文件 | 职责 | 对应 Harness 要素 |
| --- | --- | --- |
| `lifecycle/SESSION-START.md` | 会话开始检查清单 | 生命周期控制 + 重复工作检测 |
| `lifecycle/SESSION-END.md` | 会话结束检查清单 | 生命周期控制 |
| `reports/session-log-template.md` | 每次会话的持久结果记录 | 会话结果 + 持久报告 |
| `reports/repair-plan-template.md` | 失败后的结构化修复计划 | 修复计划 |
| `feedback/FEEDBACK-LOG.md` | 问题发现与修复的绑定记录 | 项目反馈回路 + finding-bound fixes |
| `assets/` | 代理可复用资产（提示词、检查清单、代码片段） | 代理资产 |

## 使用规则

1. **每会话必读**：会话开始时执行 SESSION-START 检查清单；
   结束前执行 SESSION-END 检查清单，二者缺一不可。
2. **报告先于声明**：任何"已完成"的声明都必须有对应的会话日志条目与验证输出。
3. **反馈必须闭环**：在 FEEDBACK-LOG 中记录的问题，必须绑定到具体修复
   （fix 提交、变更 ID 或明确的不修复理由），不允许只记录不处理。
4. **修复计划先行**：同一问题失败达到 3 次后，必须先写修复计划再动手，
   修复计划要经过用户确认。
