# Verification Before Completion —— 验证门

## Iron Law

> **NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE**
> 声称"完成 / 修好 / 通过"前，必须现场 RUN 验证命令、READ 输出、VERIFY 一致。
> 没有新鲜证据的成功声明等于撒谎。

## 红旗词（禁止使用，除非紧跟验证输出）

"看起来可以" / "应该没问题" / "大概是好的" / "理论上通过了" / "应该修好了"

## 验证清单

声称任何完成状态前，逐项确认：

- [ ] 本会话**刚刚**运行过验证命令（不是记忆中的历史结果）；
- [ ] 输出显示 0 failures / 预期行为真实发生；
- [ ] 对于 bug 修复：还原修复后测试回到 RED（证明测试真的在测这个 bug）；
- [ ] 验证命令覆盖了本次修改的范围。

## 适用场景（任一"完成"表述）

- 单个 Task 完成
- 全套测试通过
- bug 已修复
- 准备 merge / 准备提交 PR

## 未验证怎么办

把声明降级为"未验证"，向用户如实说明尚未运行验证命令及其原因。
